# Inference Builder — ONNX models for the Inference node

The **Inference** node (Flame and Flare) runs trained **ONNX** models. A model is either:

- a bare `<name>.onnx` file, optionally with a sidecar `<name>.json` **with the same name in the same directory** (used instead of default attributes) and an optional thumbnail; or
- an encrypted **`.inf`** package (ONNX + JSON + thumbnail) created by `inference_builder`, readable only by Flame Family products (analogous to a Matchbox `.mx`).

The JSON sidecar is "the equivalent of the XML file for a Matchbox shader".

## Workflow

1. Generate the default JSON for your model (`inference_builder -j`).
2. Edit the JSON: inputs, outputs, attributes.
3. Test the model in the Inference node.
4. Fix errors in the ONNX and/or JSON.
5. Optionally create a thumbnail.
6. Package and encrypt ONNX + JSON (+ thumbnail) into `.inf` (`inference_builder -p`).

## Files

| File | Rule |
|---|---|
| `<name>.onnx` | The model. Loadable directly in the Inference node. |
| `<name>.json` | Sidecar; same base name as the `.onnx`, same directory. |
| `<name>.onnx.png` | Thumbnail for the Load Model browser. "The root of the thumbnail file name must be the same as the ONNX model (`<name>.onnx.png`)". Expected resolution **128 × 94**. |
| `<name>.inf` | Encrypted package. |

## `inference_builder` CLI

Location: `/opt/Autodesk/<application version>/bin`. Run in a Konsole/Terminal, e.g. `./inference_builder -p <file name of the model>`.

| Option | Description |
|---|---|
| `-p` / `--package` | Create an encrypted `.inf` package. Looks for JSON and thumbnail files of the same name and packages them with the ONNX model. **A package is created even if one or both are missing.** |
| `-u` / `--unpack` | Extract the JSON and thumbnail (`.png`) files from a `.inf` package. |
| `-j` / `--write-json` | Write the ONNX model description to a JSON file: a default `.json` with the same name as the `.onnx`, in the same directory. |
| `-o` / `--output` | Output all files to the specified folder: `-o <path>` or `--output=<path>`. |
| `-h` / `--help` | Full documentation. |
| *(no option)* | Prints the content of the given ONNX model's JSON file in the terminal. |

```shell
cd /opt/Autodesk/<application version>/bin
./inference_builder -j /path/to/MyModel.onnx       # writes /path/to/MyModel.json
./inference_builder -p /path/to/MyModel.onnx       # creates MyModel.inf
./inference_builder -p /path/to/MyModel.onnx -o /path/to/out
./inference_builder -u /path/to/MyModel.inf
```

(Argument form is "`<file name of the model>`"; whether a relative/absolute path, and for `-u` whether the `.inf` file is passed, is not spelled out — the lines above are illustrative.)

## Default JSON generated by `-j`

```json
{
    "ModelDescription": {
        "MinimumVersion": "2027",
        "Name": "MyModel",
        "Description": "",
        "SupportsSceneLinear": false,
        "KeepAspectRatio": true,
        "Padding": 1,
        "Inputs": [
            {
                "Name": "inputImage",
                "Description": "",
                "Type": "Front",
                "Gain": 1.0
            }
        ],
        "Outputs": [
            {
                "Name": "outputImage",
                "Description": "",
                "Type": "Result",
                "InverseGain": 1.0,
                "ScalingFactor": 1.0,
                "ColourSpace": "Z-Depth"
            }
        ]
    }
}
```

Only the input and output **names** are extracted from the model; you must set all other values. Example: **`ScalingFactor` must be set correctly for an upscaling model** — otherwise the software can crash or memory can be corrupted during inference.

Inputs vs outputs: the JSON must cover the model's inputs, but **it is not necessary to declare as many outputs as the model has** — extra outputs can be removed from the JSON.

## Schema

Top level: a single object `ModelDescription` containing the model tokens plus `Inputs` (array) and `Outputs` (array).

### `ModelDescription` tokens

| Token | Type | Default | Description |
|---|---|---|---|
| `Description` | string | None | Short description; shown in the note attached to the Inference node. |
| `KeepAspectRatio` | boolean | `true` | Preserve the input clip's aspect ratio during automatic resize. Causes a slight loss of precision — use only if the model requires it. |
| `MinimumVersion` | string | N/A | Minimum software version that can load this model (e.g. `"2027"`). The table spells it "Minimum Version"; the generated JSON uses `MinimumVersion`. |
| `Name` | string | File name without `.onnx` | User-facing model name. |
| `Padding` | integer | `1` (no padding) | For models that only accept sizes that are multiples of N pixels. All inputs and outputs are padded automatically before inference; transparent to the user, does not affect node outputs. |
| `SupportsSceneLinear` | boolean | `false` | If `false`, scene-linear input media is converted to log before inference and back after. |
| `Inputs` | array | — | See Inputs tokens. |
| `Outputs` | array | — | See Outputs tokens. |

### `Inputs[]` tokens

| Token | Type | Default | Description |
|---|---|---|---|
| `Name` | string | Model input name | Corresponding input name in the model. Two JSON inputs may share one model input name (channel combining, below). |
| `Type` | string | `Front` | Input socket type: `Front`, `Back`, `Matte`, or `Aux`. |
| `Description` | string | Defined by socket type | Shown in the input socket tooltip. |
| `SocketColor` | RGB 8-bit values array | Defined by socket type | Socket colour override. (Exact JSON form not shown; presumably `[r, g, b]`.) |
| `Gain` | float | `1.0` | All pixels multiplied by this before inference. |
| `Channels` | string | `BGR` | Channels used for inference (see rules). |

### `Outputs[]` tokens

| Token | Type | Default | Description |
|---|---|---|---|
| `Name` | string | Model output name | Corresponding output name in the model. |
| `Type` | string | `Result` | Output socket type: `Result` or `OutMatte`. |
| `Description` | string | Defined by socket type | Shown in the output socket tooltip. |
| `SocketColor` | RGB 8-bit values array | Defined by socket type | Socket colour override. |
| `InverseGain` | float | `1.0` | All pixels divided by this after inference. |
| `ScalingFactor` | float | `1.0` | For up/downscaling models: output size relative to input. **Must be correct** (crash/memory corruption risk). |
| `Channels` | string | `BGR` | Channels output by the model. |
| `ColourSpace` | string | Defined by socket type | Colour space tag of the output media (e.g. `"Z-Depth"` in the generated default). Allowed names not listed. |

Note the British spellings `ColourSpace` vs American `SocketColor` — use exactly as written.

## Channels rules

### Inputs

- `Channels` is any combination of `R`, `G`, `B` for colour inputs, or `A` for a single-channel matte input.
- **Order matters**: `BGR` ≠ `RGB`. Default is `BGR`.
- **RGBA model input**: declare **two** JSON inputs with the **same `Name`** (same model input); set `Channels` to `RGB` on one and `A` on the other. In Batch, the two connected clips are combined into one model input.
- Same mechanism for e.g. a **6-channel** input: two `RGB` inputs assigned to the same model input.

### Outputs

| Model output channels | `Channels` value |
|---|---|
| 1 | `"A"` |
| 2 | `"RG"` or `"GR"` (the latter inverts the result) — e.g. an STMap |
| 3 | any 3-letter combination (`"RGB"`, `"BGR"`, `"GBR"`, …); order affects the result |

### Example: RGB + A feeding one RGBA model input (verbatim)

```json
{
    "ModelDescription": {
        "MinimumVersion": "2027",
        "Name": "MyModel",
        "Description": "",
        "SupportsSceneLinear": false,
        "KeepAspectRatio": true,
        "Padding": 1,
        "Inputs": [
            {
                "Name": "inputImage",
                "Channels": "RGB",
                "Description": "",
                "Type": "Front",
                "Gain": 1.0
            },
            {
                "Name": "inputImage",
                "Channels": "A",
                "Description": "",
                "Type": "Matte",
                "Gain": 1.0
            }
        ],
        "Outputs": [
            {
                "Name": "outputImage",
                "Channels": "A",
                "Description": "",
                "Type": "Result",
                "InverseGain": 1.0,
                "ScalingFactor": 1.0,
                "ColourSpace": "Z-Depth"
            }
        ]
    }
}
```

## Agent notes (derived from the source only)

- Checklist for a JSON sidecar: every model input covered (by `Name`); correct `Channels` order (default `BGR`, not `RGB`!); `Gain`/`InverseGain` match the model's expected value range; `ScalingFactor` for resolution-changing models; `Padding` if the model needs multiple-of-N sizes; `SupportsSceneLinear` true only if the model was trained on scene-linear data; `MinimumVersion` set.
- Booleans are JSON `true`/`false`; numbers unquoted; `MinimumVersion` is a **string**.

## Ambiguities in the source

- Token spelled `Minimum Version` in the table vs `MinimumVersion` in generated JSON — use `MinimumVersion`.
- `SocketColor` value format ("RGB 8-bit values array") has no example.
- Allowed `ColourSpace` values are not listed.
- What `Aux` inputs mean is not described.
- Thumbnail resolution is 128 × 94 here vs 128 × 92 for Matchbox/Lightbox thumbnails.
- `inference_builder` lives in `/opt/Autodesk/<application version>/bin` (shader_builder docs say `/opt/Autodesk/<product_home>/bin`).
- ONNX opset/runtime constraints (supported operators, dynamic shapes, precision) are not documented.
