# Flame 2027 custom shaders — Matchbox & Lightbox (overview & index)

Matchbox and Lightbox are GLSL **fragment** shaders that Flame/Flare/Flame Assist load as effect nodes. Each shader is a `.glsl` file, optionally accompanied by a sidecar `.xml` UI definition (generated by `shader_builder -x`), an optional preset file, and an optional thumbnail; it can be packaged/encrypted into a single `.mx` (Matchbox) or `.lx` (Lightbox) file.

## Matchbox vs Lightbox

| | **Matchbox** | **Lightbox** |
|---|---|---|
| What it is | Standalone image-processing fragment shader. "Not part of an established shading pipeline." | A snippet appended to **Action's** fragment shader and called inside Action's lighting loop; attached to a light. |
| Entry point | `void main()` — write `gl_FragColor` (legacy GLSL) or a `layout(location = 0) out vec4` (modern GLSL). | `vec4 adskUID_lightbox(vec4 source)` — returns the new colour **and a valid alpha**. |
| Where usable | Action, Batch/BFX, Timeline, Modular Keyer, Tools tab (see availability table). | Action only (Flame, Flare). |
| Passes | Multiple passes allowed (`Name.1.glsl`, `Name.2.glsl`, …) — one `<Shader Index=…>` per pass in XML. | Exactly one pass (one `<Shader>`). |
| Inputs | `sampler2D` uniforms become node input sockets; **max 6 node inputs** processed. | Receives `source` (incoming fragment from previous light/Lightbox); queries scene via Lightbox API (`adsk_getNormal()`, light, material, map, IBL functions…). |
| Global symbol naming | No mandated prefix. | **Every global symbol (functions, uniforms, constants…) must be prefixed `adskUID_`** to avoid clashes (clashes disable *all* loaded Lightboxes). |
| Modern GLSL | `#version 430`, `440`, `450`, `460`. | `#version 460` only (old Lightboxes ≤130 can still be combined with 460 ones). |
| `shader_builder` type switch | `-m` / `--matchbox` | `-l` / `--lightbox` |
| Package extension | `.mx` | `.lx` |
| Shipped location | `/opt/Autodesk/presets/<application version>/matchbox/shaders/` | `/opt/Autodesk/presets/<application_version>/action/lightbox/` (the docs also say `.../action/lightbox/shaders/` in one place — see Ambiguities) |
| Examples folder | `/opt/Autodesk/presets/<application_version>/matchbox/shaders/EXAMPLES/` | `/opt/Autodesk/presets/<application_version>/action/lightbox/EXAMPLES` |
| Matte | Can provide a matte to the child node via XML `MatteProvider="True"` (required if the shader operates on alpha and the alpha should be passed on). | "Lightbox must always return a matte" (the returned alpha). |

## File layout (only what is documented)

| File | Purpose |
|---|---|
| `<name>.glsl` | The shader source. "In its most basic form, a Matchbox or Lightbox is only a .glsl file" — enough for Flame to render and generate a rough UI. |
| `<name>.xml` | Sidecar UI definition, generated by `shader_builder -x`, then hand-edited. Its `Name` attribute overrides the filename in the UI even if the user loads the `.glsl`. See [xml-reference.md](xml-reference.md). |
| `<name>.1.glsl`, `<name>.2.glsl`, … | Multipass Matchbox: one file per pass (e.g. `PyramidBlur.1.glsl`, `PyramidBlur.2.glsl`). In the Load Shaders browser the user selects the **root group** `PyramidBlur.glsl` to load all passes as one effect. Use `-p` to package into one file. Matchbox only. |
| `<name>.png` | Optional browser thumbnail/proxy: **8-bit, 128 × 92 px** PNG, same folder and same base name as the `.glsl`/`.xml`. |
| `<name>.p` | Optional thumbnail (Matchbox docs: "optional .p or .png file to be used as a thumbnail"; `-u` extracts "thumbnail (.png, .p) files"). Format of `.p` is not documented. |
| `<name>.preset.xml` | Optional presets file (`<Presets>` root). See [presets.md](presets.md). |
| `<name>.mx` / `<name>.lx` | Encrypted package created by `shader_builder -p` (Matchbox / Lightbox). |

Notes:
- Any uniform whose name starts with `adsk_` is **not shown in the UI** and not considered by `shader_builder` (it is a Flame-provided value).
- If you cannot see your shader in the Load Shaders file browser, try toggling the **Mode** box between Matchbox and GLSL.
- Cross-version: a Matchbox created in a previous version works in the current one, but one created in the current version may not work in a previous version (API and XML schema updates).

## GLSL versions

| Context | Allowed GLSL | Notes |
|---|---|---|
| Linux (legacy) | 130 | "on Linux the supported version of GLSL is 130". |
| macOS | 120 | "Action does NOT comply with OpenGL core profile". An X server (XQuartz) is required for `shader_builder` to compile (`ERROR: Compiling shaders requires a valid Display`). |
| Matchbox, modern | `#version 430`, `440`, `450`, `460` | Adds double precision, packing/unpacking & bit functions, atomics, matrix determinant, fused multiply-add (see GLSLangSpec of that version). The `#version` directive **must** be in **each** `.glsl` file header. **Uniforms must be declared inside a uniform block** (Vulkan / SPIR-V rules). |
| Lightbox, modern | `#version 460` only | Multiple Lightboxes are combined into one Action shader, so recent versions cannot be mixed; old Lightboxes (up to 130) can be merged with 460 Lightboxes. Same new functions as Matchbox. |

Modern-GLSL compilation (as of 2025.1 Update) is stricter: some former warnings are now errors.

## Workflow

1. Write or paste GLSL fragment shader code (forward-declare all uniforms and the `adsk_*` APIs you use — required by both Matchbox and Lightbox so `shader_builder` reports accurate locations).
2. Run `shader_builder` to compile/test and generate the sidecar XML (`-x`) and optionally a preset template (`-t`).
3. Fix GLSL errors (`shader_builder` only writes the XML if there are no errors).
4. Edit the XML to customise the UI (names, defaults, ranges, tooltips, pages/columns, widgets such as curves, popups, colour wheels…).
5. Optionally create presets (`<name>.preset.xml`) and a thumbnail.
6. Package (optionally encrypt) with `shader_builder -p` → `.mx` / `.lx`.
7. Load in Flame/Flare/Flame Assist and test.

## `shader_builder` CLI

Location: `/opt/Autodesk/<product_home>/bin`. Help: `shader_builder --help` (full documentation).

| Option | Verbose | Description |
|---|---|---|
| `-p` | `--package` | Creates a `.mx` or `.lx` encrypted package file. |
| `-u` | `--unpack` | Extracts the xml and thumbnail (`.png`, `.p`) files from a `.mx` or `.lx` package file. |
| `-x` | `--write-xml` | Writes the sidecar `.xml` interface to a file. |
| `-l` | `--lightbox` | Sets the shader type to a lightbox operator. |
| `-m` | `--matchbox` | Sets the shader type to the standard matchbox operator. |
| `-t` | `--preset-template` | Writes the preset template to a file. |
| `-o` | `--output` | Outputs all files to another folder. |
| `-d` | `--do-not-compile` | Does not attempt compiling the shaders. Use with `-p`. |
| `-h` | `--help` | Displays full documentation. |

Options can be combined:

```shell
shader_builder -m -x myShader.glsl     # Matchbox: compile + write myShader.xml
shader_builder -l -x myLightbox.glsl   # Lightbox: compile + write myLightbox.xml
shader_builder -m -p myShader.glsl     # package/encrypt Matchbox -> .mx
shader_builder -l -p myLightbox.glsl   # package/encrypt Lightbox -> .lx
```

Successful `-x` run output (from the docs):

```text
compiling shader file scale.glsl ... [OK]
all shaders compiled ... [OK]
generating XML interface ...
creating XML file (scale.xml) ... [OK]
```

## Action Single Panel UI page names

A shader UI page has three names in its XML `<Page>` element: `Name` (expanded UI, all 6 columns), `ColName0_2` (collapsed/dual-panel page with the first 3 columns), `ColName3_5` (page with the last 3 columns). See [xml-reference.md](xml-reference.md#page).

## Related: driving shaders from the Python API

From the Python API docs (see `../api/`): `flame.batch.create_node("Matchbox", "Blur.mx")` creates a Matchbox node with a shader from the default path; a Matchbox node exposes `shader_name` (e.g. `flame.batch.get_node("Matchbox100").shader_name`).

## Ambiguities in the source (shader pages)

- Lightbox install path is given as `/opt/Autodesk/presets/<application version>/action/lightbox/shaders/` (step 3) and `/opt/Autodesk/presets/<application_version>/action/lightbox/` (step 6) on the same page.
- `shader_builder` location is `/opt/Autodesk/<product_home>/bin`; `<product_home>` is not further defined.
- The `.p` thumbnail format is never described.
- The legacy-version statements ("Linux 130", "macOS 120") coexist with the modern-version support; the docs do not state whether 120/130 remain required on current platforms for legacy (non-`#version`) shaders.
